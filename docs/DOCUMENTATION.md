# 文档标准与维护规则

用途：统一文档权威、证据和维护方式。适用范围：全部版本控制文档与新增报告。
状态：CURRENT。验证：`clinx-source-audit --check-project`；人工核对事实与命令副作用。

## 单一事实定义

[文档地图](README.md)逐份列出文档角色，分类使用：
`CURRENT`（现行权威）、`REFERENCE`（专项技术参考）、`HISTORICAL`（历史证据）、
`SUPERSEDED`（已被替代或重复、保留取证价值）。同一事实只设一个权威定义，其他文档链接它。
源码/协议常量和测试 oracle 是实现事实依据；文档不另造状态或版本。出现冲突先核对源码，
在当前权威入口解释差异，不静默把历史 PASS 或未完成事项改成现状。

每份 CURRENT 文档在开头说明用途、适用范围、状态和验证方法。工程说明以中文为主，
保留 API、类型、路径、命令、协议、错误码原标识。新增配置项说明来源、默认、必填性、
作用域与副作用；不把真实凭据写入文档。

## 状态和证据

- TARGET：目标架构或 roadmap；CURRENT_SOURCE：当前可定位源码。
- CANDIDATE / STAGED_NOT_SELECTED：有明确 manifest/hash 的候选产物。
- DEPLOYED：必须有当次安装路径、选中 release、进程 binary/hash 和服务读回证据。
- HISTORICAL：有日期、原基准、命令和结果的历史证据，不能用于声明今天的运行状态。
- PASS / FAIL 只用于实际执行结果；前置条件缺失为 BLOCKED；未执行为 NOT_RUN，
  证据不足为 NOT_PROVEN。HTTP 200、cargo build、git push 均不等于业务验收。

技术断言链接实际源码、测试或发布证据。当前命令必须可追溯到参数解析器，清楚标记
占位参数、工作目录、平台、环境与副作用；不要执行安装/重启命令来验证文档。
绝对 `/data/artifacts` 路径是现场证据索引，可能不随 clone 分发，须明确本次是否验证可达。

## 链接和变更

当前源码路径使用相对 Markdown 链接；锚点使用稳定标题。审计检查 Markdown 行内链接、
引用式链接、锚点和源文件链接，不访问外网或绝对现场路径；代码块内示例不作为链接。
不要在 CURRENT 文档中把退役路径当作可执行命令。历史报告中的原命令保留并标记历史。
如果原相对链接已失效，将链接呈现修正为带说明的历史路径或精确历史 Git 链接，
不更改其原日期、结果、失败或原语义；变更必须可 diff 审查。

重要架构变更同时更新架构、契约、测试指南及 CHANGELOG，并记录 ADR 的背景、决定、
替代方案、后果与验证。ADR 编号使用下一个未占用编号，不补造缺失的 ADR-005。
新增报告优先保存在任务证据目录；长期文档仅在现有主题不能覆盖时新增。
删除前检查引用和历史取证价值；本轮历史报告保留原路径，只增加范围说明。

## 自动化的边界

审计与 Cargo 构建共用 Rust 工具链，无 Python、Node 文档框架或第二构建系统。
源码分类清单审查新增文件及直接模块依赖；发布检查使用 Cargo targets、原生清单和
构建器名单，并可校验实际 release 文件集、hash 和 Python 污染。
静态扫描不能证明所有动态行为或事务语义；业务/网络/设备回归与人工审查不可省略。
CI workflow 存在并不证明 GitHub 分支保护已开启，分支保护是独立管理配置。
